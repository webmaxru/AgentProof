# Product limitations and feedback

These are reusable design observations, not promises of available features or
claims that an installation has been validated. Reproduce against the current
host and record target, version, full SHA, expected/actual behavior, and remaining
blockers without exposing private evidence.

| Area                           | Limitation                                                                                                                                       | Safe behavior or requested improvement                                                                                                                                                   |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Effective reviewer permissions | Historical hosts exposed mutation, shell, and cross-repository tools despite read-only selections.                                               | Keep automated specialists blocked; verify effective permissions, not prompt restraint. Request a pre-save preview that matches runtime capabilities.                                    |
| Public-packet review           | The `0.3.0` zero-tool profiles and CLI host adapter do not establish live App isolation or guarantee that a specialist will accept its boundary. | Require independently checked native zero-tool/zero-call evidence and current source bindings. Keep refusals as failures; retain legacy App gates and separately validate the new route. |
| Custom agent selection         | Availability can depend on project selection, installation source, version, and host features.                                                   | Use the exact reviewed profile; cancel instead of substituting a general-purpose agent.                                                                                                  |
| Assistance origin              | Some first-party attribution is available; external assistance is self-declared or unknown.                                                      | Preserve confidence classes; never infer authorship from code shape. A privacy-aware commit-bound attestation could improve interoperability.                                            |
| Evidence and decisions         | Checks, artifacts, comments, policy, expiry, and approvals are separate GitHub objects.                                                          | Validate exact identity and digests; preserve independent review. A native commit-bound evidence object could reduce custom integration code.                                            |
| Canvas snapshots               | Board state is mutable and can be cleared or replaced.                                                                                           | Link to authoritative GitHub records. A confirmed immutable export could aid review, but must not replace native approval.                                                               |
| Multi-agent assembly           | Independent notes can arrive late or for different heads.                                                                                        | Run manual assembly with typed fragments and fail-closed same-SHA checks; absent outputs are not fabricated passes.                                                                      |
| Personal automation inventory  | Configuration and ownership may live outside Git.                                                                                                | Keep versioned templates as inputs only and record effective permissions, owner, source revision, review date, and disabled status.                                                      |
| Repository enforcement         | Checks can run without plan entitlement for private rulesets or a separate available reviewer.                                                   | Report enforcement as blocked/not verified until both controls are exercised; never make the repository public or weaken protection implicitly.                                          |

Submit feedback only with owner-approved, non-sensitive reproductions. Neither
scanner output, a passing canary, nor completion of this checklist is a legal,
security, privacy, or compliance determination.
